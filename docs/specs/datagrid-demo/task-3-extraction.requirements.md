# Task 3: table exploration requirements

Status: implementation authorized by the user on 2026-09-19. This revision supersedes the earlier requirement to qualify business-cell OCR before image exploration. Plan: [implementation](task-3-extraction.implementation.md).

Execution: implemented and verified on controlled UIA and opaque Windows table fixtures. Release build and all 764 repository tests pass. The earlier Abacre business-reading qualification remains unresolved; this result does not claim a fresh Abacre traversal.

## User outcome

Click a detected grid in the UI mapper, then click **Explore** in its floating window. The mapper identifies the table and its header row, safely explores the selected grid, and presents the captured image with table/header outlines. Both UIA-native grids and visual/native-window candidates use this flow. The user does not choose scroll directions or configure vertical/horizontal exploration.

## Required behavior

- **E1 — Simple inspector:** preserve the existing floating-window style and grid identity. Show a short explanation and one Explore action. While running show useful progress and Stop. On completion show the image, table/header identification, capture status, Save image, and Extract. Keep direction/provider configuration out of this flow; Extract opens a separate header/schema review.
- **E2 — Explicit bounded action:** Explore authorizes scrolling only the selected table for at most 60 seconds, 32 movements, 24 captured views, and 64 MiB of PNG evidence. State the time/view limits beside the action. Discover required scroll directions automatically. Opening the inspector never scrolls.
- **E3 — Structure independent of text:** identify table/header geometry from current native or image evidence. Text OCR is not a prerequisite for this image workflow, and a successful exploration does not qualify cell transcription. Keep the existing stricter reading path intact.
- **E4 — Safe operation:** bind fresh process, window, host, and geometry; serialize against recorder automation; hide mapper decorations from captures; stop on cancellation, user takeover, target/foreground loss, changed geometry, unsupported movement, ambiguous joins, or bounds. Never edit, add, delete, sort, or filter application records. Restore the original view only while still safe, with a separate restoration result.
- **E5 — Honest image:** assemble only verified, connected captures at original resolution, retaining the header once. Preserve source pixels and geometry. A full image requires evidence for all boundaries and continuous coverage. Interrupted, unsupported, or bounded runs remain visibly partial/failed; never label the visible viewport as the full table without evidence.
- **E6 — Usable result:** allow zoom/scroll of the image, one simple structure overlay, and saving the original-resolution image. Keep captured evidence and geometry available for diagnosis. Unproven header/table geometry produces a clear reason rather than invented structure.
- **E7 — Lifecycle:** prevent duplicate runs, cancel on close/selection change/mapper teardown, keep Stop reachable during exploration, and recover the inspector after failure. Passive mapper refresh must not reset progress or discard the result.
- **E8 — Extract from available evidence:** Extract remains available for complete, partial, stopped, bounded, and restoration-failed captures whenever an image exists. If stitching failed but a source tile was retained, allow review of that single view with explicit incomplete coverage. A failure before any image was captured explains that evidence is unavailable. Extraction reads retained pixels only and requires no further scrolling or successful restoration.
- **E9 — Header and schema review:** allow users to select the header rectangle with zoom, correct column dividers, read the header labels, and edit duplicate, blank, or unreadable names. Save the reviewed physical column schema beside the capture, with source-image identity and unchanged capture/coverage/restoration receipts. A confirmed header schema does not qualify body text or prove uniform rows. Unverified horizontal coverage remains an incomplete schema even after review.
- **E10 — Visible structure and divider editing:** keep the selected header-row rectangle and full-height column divider lines legible in Fit, 100%, and 200% views. Edit column dividers exposes selection, dragging, left/right adjustment, removal of the selected divider, and explicit placement of a new divider. Dividers stay ordered inside the selected header width with valid column spacing; changed geometry requires extracting again before saving.
- **E11 — Optional Azure header reading:** Recorder settings and schema review expose Local OCR or Azure OpenAI GPT-5.6 Sol with low reasoning (Light). Store the Azure resource endpoint and deployment name locally and the API key in Windows Credential Manager. Test connection with synthetic header pixels. Extraction sends only the selected header-cell crops, binds literal names to fixed physical column keys, preserves duplicate/blank/unreadable names, and still requires review. Failed, refused, incomplete, or mismatched responses must not save a partial schema or silently substitute another model/provider. Cloud reading never changes column geometry or upgrades capture coverage.
