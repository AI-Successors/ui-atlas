# Recording bundle v1

The `.mlrec` format is a ZIP container identified by `ui-atlas.recording/1`. Entry names use forward slashes and UTF-8. Raw entries are append-only during a live session and immutable after finalization. Derived entries may be rebuilt from raw inputs into a new bundle; existing bundles are never edited in place.

Required entries:

| Entry | Role |
| --- | --- |
| `manifest.json` | versions, outcome, consent, target policy, privacy, retention, counts, and payload file table |
| `raw/input-events.jsonl` | ordered scoped input timing; printable key identity and text are redacted by default |
| `raw/interactions.jsonl` | optional ordered causal actions, attempts, source controls, result frames, outcomes, and diagnostics |
| `raw/capture-health.jsonl` | bounded component status and recoverability |
| `raw/observations/frame-NNNNNN.json` | Win32 windows, bounded UI Automation, trigger, and frame linkage |
| `raw/frames/frame-NNNNNN.png` | optional scoped application/owned-popup pixels |
| `derived/statebook.json` | representative frames and action-to-observation episodes |
| `hashes.sha256` | SHA-256 for every other archive entry |

The manifest file table contains each payload path, length, media type, SHA-256, and immutable flag. Outcomes are `complete`, `partial`, `cancelled`, and `failed`. Partial and cancelled bundles remain validateable if retention policy permits them. Target metadata may include product version, original binary filename, company, and product name when Windows permits inspection; executable paths are never recorded.

The attended CLI captures a baseline first, activates the sealed target once, and automatically arms one released click in the selected root-owner scope. After the click, the Slow & Rich sequence captures immutable action evidence immediately and at 50, 200, and 800 milliseconds, then captures the materialized result at the five-second boundary. The target stays active and the next click is armed after the materialized UIA worker completes, times out, or returns a bounded partial result. The user can still focus the console and type `[N]` to explicitly arm one click or `[T]` to wait for two clicks without an intermediate capture; `[D]` and `[C]` finish or cancel while the console command wait runs concurrently with the target-click wait.

Before target activation, the CLI remembers the foreground command window and restores it after the materialized observation completes. Screenshot graphics and image-format argument failures are recoverable: the frame retains Win32/UIA evidence with an empty screenshot reference and records degraded capture health instead of terminating the session.

Each observation enumerates the selected top-level root and visible same-process top-level windows whose root-owner chain leads to it, including owned menus, dialogs, and tool popups. UI Automation descendants are collected separately for every enumerated window when that capture phase requests UIA. Popup deltas are written only after two HWND-scoped UIA snapshots surrounding the PNG agree on bounds and connected interactive structure; rejected candidates produce health evidence but no frame. An independent top-level window with no ownership relationship is outside v1 scope even when it belongs to the same process. Frame fields `episodeSequence`, `capturePhase`, `postTriggerDelayMs`, and `actionObservedUtc` preserve the raw timing relationship. The rebuildable statebook records arm/action/settled boundaries and selects materialized frames plus structurally distinct 800-millisecond transient observations as graph representatives; earlier evidence remains immutable in the bundle.

Screenshot health records identify whether a frame used `windows-graphics-capture`, `gdi-window-fallback`, or was unavailable. Native composition is limited to 32 scoped windows, five cumulative seconds, and 32 MiB of intermediate PNG data per frame. When a cumulative limit is reached, the health stream marks the frame partial and uncaptured regions remain blank. They never contain exception text, a file-system path, or captured application text.

Readers must inspect archive metadata before reading payloads. V1 rejects traversal, absolute or drive paths, empty segments, path aliases, reserved device names, case or Unicode-normalization collisions, links/reparse entries, count/size/ratio excess, invalid UTF-8, malformed JSON, duplicate JSON properties, undeclared or missing payloads, and checksum mismatches. Observation and screenshot evidence must use the sequence-bound `raw/observations/frame-NNNNNN.json` and `raw/frames/frame-NNNNNN.png` namespaces; unreferenced or out-of-namespace images are invalid. Recordings have no frame-count ceiling. Accepted recordings retain safety bounds of 50,000 input events, 20,000 automation observations per frame, 32 scoped windows per frame, 100,000 archive entries, and 512 MiB uncompressed total. New frames may optionally declare `full-root`, `popup-delta`, or `control-delta` scope, the HWNDs actually observed, absolute screenshot bounds, and their baseline sequence; fields absent from older bundles retain full-frame semantics. Owned modal dialogs opened from Ribbon launchers are preserved as full-root frames containing the current Ribbon surface and the stable dialog UIA tree. When no image was retained, legacy zero screenshot bounds are ignored; new writers only set screenshot bounds after capture succeeds. Popup UI Automation is capped at about one second and 600 visited elements, while first-tab observations use a two-second bound. Current policy limits are encoded in `BundleLimits` and are part of the validator behavior.

`raw/interactions.jsonl` distinguishes gesture from semantic action and records `User`, `AutoExplorer`, and derived candidates separately. Repeated attempts share an operation ID. Typed values are never included; keyboard activity is represented only as a redacted grouped action and input-event references. Older bundles may omit the stream and remain valid.

Migration rule: a reader must reject an unknown major identifier. Additive optional fields may be introduced without changing the identifier. A semantic or required-field change requires a new identifier and an explicit migration that writes a new bundle. Published schemas cover the [manifest](../schemas/recording-bundle-v1.schema.json), [frame observations](../schemas/recording-frame-v1.schema.json), [interaction observations](../schemas/recording-interaction-v1.schema.json), and [derived statebook](../schemas/recording-statebook-v1.schema.json).
